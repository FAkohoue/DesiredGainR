# DesiredGainR critical re-audit — 1 August 2026

> **Superseded historical audit.** This report describes the package
> snapshot reviewed on 1 August 2026. Its scientific release blockers
> were subsequently corrected in the current 0.5.0 source. It is
> retained only as an auditable record of the remediation process; use
> `MATURITY.md`, `NEWS.md` and `inst/validation/` for the current
> evidence and readiness assessment.

## Executive verdict

The new snapshot is materially better than the 31 July version. It
resolves most of the earlier mechanical and simulation-contract findings
and expands the test suite from 545 to 696 passing expectations. The
package source builds and all six vignettes render.

It is nevertheless **not release-ready and not yet safe to present as an
expert-validated quantitative-genetics implementation**. The ordinary
source package check has one error, the CRAN-style check has two errors,
the new no-skip CI job is guaranteed to fail, and three newly advertised
scientific capabilities do not implement what their documentation says:

1.  DGSI’s default holdout selection uses rows that already influenced
    every fitted replicate;
2.  Mallard’s claimed absolute response constraint constrains
    unnormalised `G b`, not the actual response `i G b / sqrt(b' P b)`,
    while the method labelled Harville is not Harville’s proportionality
    method; and
3.  residual covariance draws in
    [`propagate_covariance_uncertainty()`](https://FAkohoue.github.io/DesiredGainR/reference/propagate_covariance_uncertainty.md)
    are never passed to the simulation.

These are scientific validity issues, not polish.

## Release blockers

### R1. `R CMD check` fails in the `run_dgsi()` example

The example at `R/run_dgsi.R:139-168` generates candidate data whose
estimated phenotypic covariance is incompatible with the supplied `G`.
The new guard correctly stops, but the package’s own documented example
therefore fails:

> smallest eigenvalue of P - G is -0.586 against a sampling threshold of
> -0.378

**Fix:** supply a compatible named `P` in the example, or generate
`ref_data` from a covariance that is admissible with `G`. Do not set the
override merely to make the check pass. Require a clean standard and
CRAN-style check before release, then correct `cran-comments.md`, which
currently claims 0/0/0.

### R2. The default DGSI “holdout” is data leakage

Every stochastic replicate is optimized on all rows at
`R/run_dgsi.R:521-566`. Only after fitting finishes are `holdout_rows`
sampled and used to choose among those already fitted replicates at
lines 584-618. The comment at line 583 that the rows “played no part in
producing” the coefficients is therefore false.

The guide, Rd page, NEWS and returned `optimism$note` all call this
unbiased. It is not. Changing the alleged holdout observations can
change the fitted coefficients before holdout scoring.

**Fix:** split before optimization. Fit all replicate searches on the
training rows and choose among them on untouched validation rows. If
coefficients are then refitted on all data, report the post-selection
fit separately and do not call its objective an unbiased performance
estimate. External `validation_data` should be allowed to select the
replicate, not merely assess the winner chosen elsewhere.

Also update `print.desired_gain_index()`: it always says the result is
the biased minimum over replicates even when the object claims a holdout
rule.

### R3. The newly advertised restricted-index families are not all valid

#### Mallard

The code enforces `C G b = target` and stores that quantity as
`achieved_response`. Actual expected response is

`i G b / sqrt(b' P b)`.

Because index scale is arbitrary, constraining unnormalised `G b` cannot
impose an absolute response. In an independent probe, targets
`(0.4, 0.1)` produced stored “achieved” values `(0.4, 0.1)` but actual
expected responses `(0.995227, 0.248807)`. The existing test checks only
their ratio, despite its title claiming absolute responses.

**Fix:** remove the absolute-gain claim unless the normalized nonlinear
constraint is solved with a stated selection intensity. Rename the
current calculation as an unnormalised direction constraint if retained.

#### Harville

The implementation defines an arbitrary shrinkage
`penalty / (1 + penalty)` between unrestricted and zero-response
coefficients. Harville’s 1975 paper is *Index selection with
proportionality constraints*, not a generic soft-penalty method. The
package therefore attaches a historical name and citation to a locally
invented regularization rule.

The citation is also wrong: the paper was authored by C. D. Kemp and D.
A. Harville and its DOI is `10.2307/2529722`; `paper/paper.bib` omits
Kemp and uses `10.2307/2529724`.

**Fix:** implement and verify the published proportionality formulation,
or rename the current method without attributing it to Harville. Add
coefficient and response checks against an independent reference
implementation.

### R4. Residual covariance uncertainty is drawn and then ignored

[`draw_covariance_pairs()`](https://FAkohoue.github.io/DesiredGainR/reference/draw_covariance_pairs.md)
correctly constructs `G*`, `E*` and `P*`. However,
[`propagate_covariance_uncertainty()`](https://FAkohoue.github.io/DesiredGainR/reference/propagate_covariance_uncertainty.md)
rebuilds the setup with only `drawn$G` at
`R/covariance_uncertainty.R:244-259`; neither `drawn$E` nor `drawn$P` is
ever used. AlphaSimR residual variance is instead recreated from the
fixed `h2`. Consequently, changing `P` or `residual_df` does not
propagate the advertised residual uncertainty through the simulation.

**Fix:** provide the drawn residual covariance to the
phenotype-generation model, or remove `P`/`residual_df` and describe the
function as genetic- covariance-only sensitivity analysis. Add a test
proving that two different residual models change the distribution while
holding the genetic draws fixed.

### R5. The new full-dependency CI job must fail by construction

The workflow stops if any test skips. With every dependency and both
guide editions installed, the current suite still skips:

- the test of behavior when exactly one guide edition is absent;
- the test of behavior when an optional dependency is absent; and
- the complementary guide-edition condition.

This exact local configuration produced three skips. The workflow at
`.github/workflows/R-CMD-check.yaml:111-132` will therefore never pass.

**Fix:** separate dependency-required tests from intentional
absence/edition branch tests. In the full-dependency job, run a tagged
subset that must not skip, or turn mutually exclusive branch checks into
direct unit tests using mocked paths/dependency availability.

## High-priority correctness issues

### H1. Checkpoint fingerprints are neither complete nor collision-resistant

`digest_of()` keeps only the first 4,096 serialized bytes and
concatenates byte values without a cryptographic hash
(`R/optimize_desired_gains.R:93-102`). A change late in a 100 x 100
founder haplotype matrix produced an identical fingerprint in an
independent probe.

The fingerprint also omits mode-specific inputs such as
`economic_weights`, `target_gains`, `focal_trait` and `gain_floors`,
plus candidate-pool settings.

**Fix:** hash the complete serialized objects with a stable digest and
include all scientific and search inputs. Add tests changing the first
and last founder locus and every objective parameter individually.

### H2. Optimizer Monte Carlo uncertainty is still handled incorrectly

Replicate outcomes and their covariance are computed by
`.dgr_evaluate_direction()`, but only means and marginal standard errors
are stored. Replicates and covariance are discarded.

`.dgr_scalarised_error()` then uses the mean marginal error for
economic, target and constrained modes. That is not the uncertainty of:

- `w' outcome` in economic mode;
- the nonlinear target distance in target mode; or
- the focal trait in constrained mode.

Repeated directions are evaluated with the same base seeds, yet the
pooling code treats those identical runs as independent replication and
shrinks the standard error. Frontier resampling also perturbs objectives
and directions independently despite shared seeds and within-direction
covariance.

**Fix:** retain replicate-level outcomes, scalarize each replicate under
the actual mode, and estimate the scalar variance directly. Use new
seeds for intentional replication. Preserve within- and across-direction
common-random- number covariance when estimating frontier membership.

### H3. The optimizer can enter a non-terminating loop

After the initial design, proposals come from a fixed `n_candidates`
pool. Once all pool directions are excluded, every acquisition value is
`-Inf`, [`which.max()`](https://rdrr.io/r/base/which.min.html) returns
an already evaluated point, its result is pooled, and the number of
unique evaluated directions does not increase. The loop condition at
line 590 remains true forever.

This is reachable when `budget` exceeds the number of unique initial
plus pool directions; no validation prevents it.

**Fix:** validate the maximum unique budget, stop when no finite
acquisition remains, or generate new candidate pools adaptively. Add a
tiny-pool regression test.

### H4. DGSI optimized directions lose their trait names

[`stats::rnorm()`](https://rdrr.io/r/stats/Normal.html) at
`R/run_dgsi.R:539` returns an unnamed proposal. When such a proposal
improves the objective, `optimised_d` is stored unnamed. The new
`summary.desired_gain_index()` indexes it by trait name, producing an
absent or empty `Optimised_gain` column. This was reproduced
independently.

**Fix:** restore `names(proposal) <- trait_cols`, and make
[`summary()`](https://rdrr.io/r/base/summary.html) validate the object
schema rather than silently accepting a length-zero lookup.

### H5. Estimated-`P` compatibility allowance is unit-dependent

The sampling allowance is

`-2 * sqrt(p / n) * max(diag(P))`.

It compares the smallest raw eigenvalue of `P - G` with the largest
marginal variance. This changes under a harmless rescaling of one trait.
For example, `P = diag(10000, 1)` and `G = diag(10000, 2)` is accepted
within the allowance, whereas expressing the first trait in units 100
times smaller makes the same biological pair inadmissible.

**Fix:** assess the residual in a standardized/generalized-eigenvalue
space, or use a bootstrap/sampling distribution tied to the covariance
estimator. Retain the strict stop, but make its tolerance invariant to
trait units.

### H6. Covariance-propagation summaries are mislabeled or fragile

- `point_estimate` is the average across covariance draws, not an
  evaluation under `setup$G_target`.
- `rank_churn` ranks the row mean of objectives in their raw units. That
  is unit-dependent and undefined as a preference for a Pareto problem.
- `n_replicates = 1` is allowed but produces all-`NA` Monte Carlo
  variances and can fail when choosing the “dominant” source.
- One supplied direction is allowed, but dimension dropping can pass a
  vector to `.dgr_non_dominated()`, which expects a matrix.
- The exported propagation function has no direct tests; existing tests
  cover only covariance-pair generation.

**Fix:** evaluate the original setup explicitly, require a declared
scalarization for rank churn, handle or reject one replicate, preserve
matrix dimensions, and add end-to-end tests.

### H7. Diversity defaults remain internally incompatible and too permissive

[`founder_population()`](https://FAkohoue.github.io/DesiredGainR/reference/founder_population.md)
defaults to no marker panel, while
[`optimize_desired_gains()`](https://FAkohoue.github.io/DesiredGainR/reference/optimize_desired_gains.md)
defaults to `include_diversity = TRUE`. The default optimizer call
therefore errors on a default setup.

On an AlphaSimR version where QTL-marker disjointness cannot be
verified, the optimizer only warns and continues even though the
resulting diversity axis may contain loci under selection. The
covariance-propagation function checks only that a panel exists and does
not check `marker_qtl_overlap` at all.

**Fix:** default diversity to `FALSE`, or create a verified panel by
default. Require `marker_qtl_overlap == FALSE` unless the caller
supplies an explicit experimental override recorded in provenance.

### H8. Multi-environment stability is described as appended but is not usable

`include_stability = TRUE` returns a separate `stability` list. It does
not append variables to `labels`, `G`, `P` or `economic_weights`, and
[`restricted_index()`](https://FAkohoue.github.io/DesiredGainR/reference/restricted_index.md)
accepts only trait selectors, not the arbitrary contrast matrix returned
here. Thus the guide’s claim that stability contrasts can be passed into
the existing index workflow is not implemented.

[`widen_environments()`](https://FAkohoue.github.io/DesiredGainR/reference/widen_environments.md)
also silently takes the first record when a genotype has duplicate rows
within an environment.

**Fix:** either return a fully augmented, usable index problem or
provide an API that consumes the contrast matrix. Reject duplicate
genotype-environment keys before widening. Label
`1 - mean(environment correlation)` as a heuristic, not an exact
interaction-variance share for every correlation structure.

### H9. The packaged PDF is not tagged

The PDF renders cleanly, has 17 pages and includes bookmarks, but
structural inspection reports `Tagged: no`, no `/StructTreeRoot`, no
`/MarkInfo`, and no document language.
[`open_desiredgain_guide()`](https://FAkohoue.github.io/DesiredGainR/reference/open_desiredgain_guide.md)
and its Rd page explicitly call it “the tagged PDF.”

**Fix:** produce a genuinely tagged PDF with language and reading-order
structure, or remove the accessibility claim. Add a release test for PDF
structure if “tagged” remains promised.

### H10. The published-data reproduction is only a partial identity check

The frozen numbers verify that published Pesek-Baker gains are
proportional to the published desired-gain vector. The package is then
tested on a different, internally generated covariance matrix. This does
not reproduce published coefficients or rankings through DesiredGainR.

The article explicitly provides its datasets through BioStudies and
publishes the Method 1 coefficients, so the claim that the calculation
cannot be reproduced should be revisited. The package also cites the
wrong article title: the DOI resolves to *Estimating optimum and base
selection indices in plant and animal breeding programs by development
new and simple SAS and R codes*, not the title stored in
`R/data-rahimi.R`.

**Fix:** retrieve the archived matrices/data under their license, freeze
their checksums and provenance, and reproduce coefficients, responses
and rankings with explicit tolerances. Keep the current identity check
as a smaller supplementary test.

### H11. Desired-gain evaluation changes the definition of merit

For Pesek-Baker and Yamada, the package invents implied economic weights
`G^-1 P G^-1 d` and then reports `R_HI` and aggregate merit under that
derived objective. A different desired-gain direction gets a different
definition of net merit, so these values are not directly comparable
with Smith-Hazel or another desired-gain index under one common breeding
objective.

**Fix:** when economic weights were not supplied, label these criteria
as being relative to an implied objective and do not use them for
cross-method merit comparisons. Prefer `NA` for net-merit criteria
unless the user supplies a common `aggregate_weights` vector.

## Release engineering and documentation issues

### E1. CI hardening is incomplete

- The lint step calls
  [`lintr::lint_package()`](https://lintr.r-lib.org/reference/lint.html)
  but never fails when lints are returned.
- The pkgdown workflow still warns and publishes when the guide HTML is
  missing, knowingly leaving a 404.
- `cran-comments.md` claims 0 errors, warnings and notes despite the
  reproducible example failures.
- The release checklist records failures but exits successfully and
  ignores notes in its clean-check decision.

### E2. Citation and release metadata are still inconsistent

`DESCRIPTION`, `CITATION.cff`, `inst/CITATION` and `.zenodo.json` use
different software titles. `NEWS.md` calls 0.5.0 “in development,” while
`CITATION.cff` declares a release date and `cran-comments.md` describes
a submission.

**Fix:** define one title/version/release status source and generate the
other metadata. Add the software DOI only after it exists.

### E3. Feature maturity documentation is stale and does not ship

`MATURITY.md` says versions “up to 0.5.0” have the DGSI unit defect even
though this 0.5.0 tree contains the fix. It omits the new propagation
and multi-environment functions and says the optimizer conditions only
on fixed covariance without pointing to the new outer-loop function. It
is excluded by `.Rbuildignore`, so installed users cannot read it.

### E4. The upstream “adapters” are mostly a matrix validator

`source` is recorded but does not drive package-specific extraction. The
ASReml named-vector parser recognizes only simple trait tokens split on
`[:.!]`; real fitted-object variance-component names are often more
complex. For sommer, breedR, BGLR and StageWise, the caller must extract
the covariance matrix themselves.

**Fix:** describe this honestly as
`validate_covariance()`/[`import_covariance()`](https://FAkohoue.github.io/DesiredGainR/reference/import_covariance.md)
unless tested extractors for actual fitted objects are added.

### E5. Remaining repository and method debt

- The legacy example CSVs are excluded from the build but still remain
  in the repository.
- `scripts/build.R` is a long interactive scratch script containing
  duplicate site builds, package removal, RStudio-only restart calls and
  references to unrelated old files. Replace it with a short
  reproducible build script.
- [`bend_covariance()`](https://FAkohoue.github.io/DesiredGainR/reference/bend_covariance.md)
  now reports ASRgenomics’ aggressive changes honestly, but it still
  offers only the method that changes trait variances and targets a
  condition number near 100. Add a trait-covariance-specific repair
  option or keep this explicitly experimental.
- `print.desiredgainr_index()` reports the requested selected count
  rather than the actual count when hard culling returns fewer
  candidates.
- The package still lacks a completed CRAN release, software DOI,
  submitted methods paper and independently reproducible
  breeding-program case study.

## Prior findings now genuinely resolved

The following changes were confirmed and should be retained:

- malformed Rd mathematics is fixed;
- both guide editions ship, HTML is the default, and the source renders;
- the hard-coded citation version was removed;
- DGSI converts SD-unit gains before raw-scale solving and passes unit
  invariance tests;
- classical theoretical transmitted response is reported separately from
  the empirical selected-candidate differential;
- count and seed validation is substantially stronger;
- simulation cycle 0/1 semantics are corrected;
- SimParam state is deep-cloned and effective thread count is recorded;
- marker identity mismatches now stop rather than silently falling back;
- full clonal covariance calibration and clonal phenotype replication
  were added;
- estimated-`P` compatibility status and override provenance are
  returned;
- QTL segregation and marker-based relationship are reported separately;
- duplicate optimizer pool points are excluded in the ordinary path;
- S3 [`coef()`](https://rdrr.io/r/stats/coef.html),
  [`predict()`](https://rdrr.io/r/stats/predict.html) and summary
  infrastructure exists, although the DGSI summary defect above remains;
- source CI now covers R-devel, oldrel, minimum R, Windows and macOS;
  and
- generated Rd files, examples, tests and vignettes otherwise pass.

## Recommended repair order

### Gate A — release and scientific validity

1.  Make both package checks clean and correct `cran-comments.md`.
2.  Replace the leaking DGSI holdout and all associated claims.
3.  correct/remove the Mallard and Harville implementations and
    citations.
4.  Make covariance propagation use residual draws, then add end-to-end
    tests.
5.  Repair the guaranteed-failing full-dependency CI job.

### Gate B — optimizer reliability

6.  Replace the truncated fingerprint with a complete stable hash.
7.  Retain replicate outcomes/covariances and compute mode-correct
    uncertainty.
8.  prevent optimizer pool exhaustion loops.
9.  Fix named DGSI optimized directions and summary output.
10. Make estimated-`P` compatibility unit-invariant.
11. Make diversity defaults and disjointness guarantees internally
    coherent.

### Gate C — expert-quality evidence and delivery

12. Complete the real published-data reproduction.
13. Make multi-environment stability operational rather than
    descriptive.
14. Correct PDF accessibility, metadata, maturity and CI claims.
15. Add real upstream adapters, a case study, DOI, methods paper and
    CRAN release.

## Bottom line

The package has moved from a broad implementation-quality problem to a
smaller set of identifiable scientific and release defects. That is real
progress. However, the newly added restricted-index and
covariance-propagation layers currently increase apparent breadth faster
than validated breadth. For an expert-quality release, correctness and
claim discipline should now take priority over adding further methods.
