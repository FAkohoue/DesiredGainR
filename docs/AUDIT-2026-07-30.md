## 1. Overall assessment

The package is well above the average R package on *discipline*: input
validation, provenance tracking, refusal to silently substitute a
prediction covariance for a genetic covariance, and explicit separation
of desired gains from economic weights. That posture is the package’s
main asset and it is unusual in this domain.

The gap is between that posture and the *statistical content*. Three of
the reported quantities are internally inconsistent or scale-ambiguous,
the DGSI optimiser targets a quantity that is not the classical expected
genetic response, uncertainty in the estimated `G`/`Γ` is nowhere
propagated, and the index families a selection-index specialist would
look for first (restricted, predetermined-proportional-gain,
Smith–Hazel/LGSI baselines) are absent. As it stands the package is a
solid, honest scoring engine; it is not yet a reference implementation
an expert panel would adopt without changes.

## 2. Strengths

**Scientific hygiene.**
[`run_dgsi()`](https://FAkohoue.github.io/DesiredGainR/reference/run_dgsi.md)
refuses to run without `G`;
[`run_qgsi()`](https://FAkohoue.github.io/DesiredGainR/reference/run_qgsi.md)
refuses to fabricate `W`;
[`estimate_genetic_covariance()`](https://FAkohoue.github.io/DesiredGainR/reference/estimate_genetic_covariance.md)
labels its estimand rather than calling every covariance “genetic”;
accuracy and MSPE are withheld unless `true_G` is supplied;
`observed_selection_differential` is explicitly not called realised
gain. This is exactly the discipline that is usually missing in
breeding-index code, and it is enforced in code, not only in prose.

**Provenance and auditability.** `covariance_provenance`,
`transformation`, `missing_data`, `assumptions`, and the equation
references travel with the result object. A reviewer can reconstruct
what was done from the fitted object alone.

**Numerical care.** Symmetrisation of user matrices, relative-tolerance
symmetry and PSD checks, spectral Moore–Penrose inverse with reported
rank for rank-deficient `Φ`, ridge terms on both solves, and rejection
of negative model variances. The `.dgr_qg_symmetric_matrix()` /
`.dgr_check_psd()` helpers are correct and consistently applied.

**Correct core algebra where it is implemented.** The Pesek–Baker
coefficient `b = P⁻¹G(GᵀP⁻¹G)⁻¹d` is correctly formed; the QGSI score,
`E(I)=tr(WΓ)`, `w'Γw`, and `2tr(WΓWΓ)` are correct for Gaussian `γ`; the
two `Γ` estimators match the cited equations including the divisor `g`.

**Stability reporting.** Replicate diagnostics, plateau detection,
Spearman rank-correlation across replicates, coefficient CV, and Jaccard
selected-set agreement are more than most index packages report, and
automatic best-replicate selection removes a manual cherry-picking step.

**Lightweight dependencies.** `data.table`, `stats`, `utils` only.
Installs anywhere, no compilation, no dependency drift risk.

**Infrastructure basics present.** MIT licence with LICENSE file,
roxygen docs, testthat 3e, R-CMD-check on three OSes, pkgdown site with
favicons, issue templates, NEWS.md, CITATION, CITATION.cff, logo.

## 3. Weaknesses — correctness and statistics (highest priority)

### 3.1 DGSI: `dg` units are ambiguous and probably misinterpreted by users

[`run_dgsi()`](https://FAkohoue.github.io/DesiredGainR/reference/run_dgsi.md)
documents `dg` as “desired gains in the analysis scale”, and
`scale_traits` defaults to `FALSE`, so `X` stays in raw trait units. But
`realised_response()` divides by the candidate-column SD:

``` r
base_sd <- apply(matrix, 2L, stats::sd)
response <- (colMeans(matrix[keep, ]) - colMeans(matrix)) / base_sd
```

So the quantity compared with `dg` is always in candidate-SD units. A
breeder who writes `dg = c(YLD = 1.5)` meaning 1.5 t/ha silently gets a
target of 1.5 phenotypic SD. `inst/examples/demo_pipeline.R` does
exactly this. Either rename the argument (`dg_sd`), or transform `dg` by
`base_sd` internally, or require `scale_traits = TRUE` when `dg` is on
the SD scale. Document the convention in the `@param` text, not only in
the vignette.

### 3.2 DGSI optimises an empirical selection differential, not expected genetic response

The classical desired-gain index has a closed-form guarantee: with
`b = P⁻¹G(GᵀP⁻¹G)⁻¹d`, the *expected genetic response*
`R = i·Gb/√(bᵀPb)` is proportional to `d`. The package computes `b` from
that formula but then scores it against the realised standardised mean
shift of the top-`n_select` candidates, and hill-climbs over `d`. That
is a different estimand, it is a step function of `b` (hence the need
for a stochastic search), and it is evaluated on the same candidates
that are then selected.

Consequences: - The closed-form solution is never reported as a
reference point. Add it. - `R = i·Gb/√(bᵀPb)`, the index accuracy
`ρ_HI`, and the achieved-vs-desired gain ratio are never returned. These
are the numbers a breeder is asked for. - Best-of-`n_rep` selection on
the training candidates is optimistically biased. The `validation_data`
slot evaluates the winner but does not participate in choosing it.
Consider selecting the replicate on held-out data, or reporting the
optimism gap. - Results depend on `n_rep`: increasing it changes the
answer, which is awkward for a package that advertises auditability.

### 3.3 QGSI: expected per-trait gain uses the wrong index SD

``` r
expected_gain <- selection_intensity * Gamma %*% weights / sqrt(linear_variance)
```

`linear_variance` is `wᵀΓw`. But `expected_net_merit_response` two lines
earlier uses `sqrt(index_variance) = sqrt(wᵀΓw + 2tr(WΓWΓ))`. The
regression of `γ` on `I` gives `R_γ = i·Cov(γ, I)/σ_I`, and `σ_I` is the
*total* index SD. Dividing by the linear part alone inflates every
per-trait gain whenever `W ≠ 0` — that is, in every genuine QGSI run.
This looks like the LGSI formula carried over unchanged.

`tests/testthat/test-qgsi-theory.R:78` asserts the current formula, so
the test suite locks the behaviour in rather than checking it. Verify
against Supplementary Eq. 16 of Cerón-Rojas et al. (2026) and, whichever
way it resolves, add a comment in the code stating which `σ` the
equation uses.

### 3.4 QGSI: squared accuracy ignores the covariance it just computed

``` r
merit_index_covariance <- linear_variance + 2*tr(W %*% Gamma %*% W %*% true_G)
...
accuracy_squared <- index_variance / merit_variance
```

`ρ² = Cov(H,I)² / (Var(I)·Var(H))`. The code returns `Var(I)/Var(H)`,
which equals `ρ²` only when `Cov(H,I) = Var(I)` — i.e. only when `I` is
the *optimal* (MSPE-minimising) predictor of `H`. The package accepts
arbitrary user-supplied `w` and `W`, so that identity generally fails,
and the code computes `merit_index_covariance` explicitly, confirming it
is not assumed equal. Either use the general formula or document and
enforce the optimality condition.

Related: the package never states the identification `θ = w, D = W`
(index coefficients equal economic weights) under which the paper’s
genomic results hold. That assumption is doing real work and should be
explicit, with its conditions.

### 3.5 QGSI: `Γ` is centred even when `center_traits = FALSE`

`.dgr_qg_estimate_gamma()` starts with
`X_cov <- sweep(X, 2, colMeans(X), "-")` unconditionally. If the user
sets `center_traits = FALSE` (because their weights refer to an
uncentred origin — a legitimate choice for a quadratic index, where the
origin determines whether curvature means stabilising or disruptive
selection), the scores use uncentred `γ` while `Γ`, `E(I) = tr(WΓ)`, and
all variance formulas use centred `γ`. The theoretical block then does
not describe the index that was actually computed. Either centre
consistently, or warn.

### 3.6 Sampling error in `G`, `P`, and `Γ` is nowhere propagated

Every reported quantity treats the covariance matrices as known
constants. In practice `G` comes from a multi-trait REML fit on tens to
a few hundred genotypes and is badly conditioned; index coefficients are
notoriously unstable under that noise. For a package whose selling point
is auditability, this is the largest scientific omission. Minimum viable
additions: bootstrap or delta-method standard errors for `b` and for the
expected gains; a sensitivity analysis that perturbs `G` within its
sampling distribution and reports the resulting rank churn; a bending /
shrinkage option (`nearPD`, Ledoit–Wolf) for non-PSD or ill-conditioned
REML output, which the package currently only rejects.

### 3.7 Degenerate default when `ref_data` and `P` are both omitted

With `P = NULL` and `ref_data = NULL`, `P` becomes `cov(X_candidates)`.
If `G` was also derived from the same candidates (as in the README,
vignette and demo), `P ≈ G`, so `P⁻¹G ≈ I` and the index collapses
towards `b ∝ d`. All three shipped examples do this. At minimum, warn
when `P` and `G` are numerically close; better, refuse the combination
or document it prominently.

### 3.8 Shipped examples contradict the package’s own doctrine

`R/estimate_genetic_covariance.R` and both narrative documents state
that raw phenotypes cannot identify genetic covariance. Then
`inst/examples/demo_pipeline.R:9` computes
`G <- stats::cov(as.matrix(values[, ..traits]))` from
`example_pheno.csv`, and README/vignette do the same on
[`rnorm()`](https://rdrr.io/r/stats/Normal.html) data. This undercuts
the package’s credibility with exactly the audience it targets.

### 3.9 Magic constants and undocumented objective shape

`objective()` uses `denominator <- pmax(abs(dg), 0.25)`. The 0.25 floor
changes the relative weighting of traits with small desired gains and
appears in no documentation. Expose it as an argument or justify it in
`@details`. Similarly,
`proposal_sd <- sd_scale * pmax(abs(centre), 0.05)` hides a second
constant.

### 3.10 Inconsistent tie-breaking

[`run_qgsi()`](https://FAkohoue.github.io/DesiredGainR/reference/run_qgsi.md)
breaks ties deterministically by candidate ID.
[`run_dgsi()`](https://FAkohoue.github.io/DesiredGainR/reference/run_dgsi.md)
uses `order(score[pool], decreasing = TRUE)`, so ties resolve by row
order — results change if the input rows are reordered. Make DGSI match
QGSI.

## 4. Weaknesses — API and software engineering

**[`set.seed()`](https://rdrr.io/r/base/Random.html) mutates the
caller’s RNG.**
[`run_dgsi()`](https://FAkohoue.github.io/DesiredGainR/reference/run_dgsi.md)
calls `set.seed(as.integer(seed))` and never restores `.Random.seed`. A
package should save and restore it (or use
[`withr::with_seed`](https://withr.r-lib.org/reference/with_seed.html)).
This silently changes downstream results in a user’s simulation script.

**No methods for `desired_gain_index`.** `print`, `summary`, `plot`
(objective trace, coefficient stability, achieved-vs-desired gain),
`coef`, and `predict` (apply fitted coefficients to a new candidate set)
are all absent. [`predict()`](https://rdrr.io/r/stats/predict.html) in
particular is what makes an index reusable across cycles;
`validation_data` only covers fit time.

**Pipeline is a lossy pass-through.**
[`run_dgsi_qgsi_pipeline()`](https://FAkohoue.github.io/DesiredGainR/reference/run_dgsi_qgsi_pipeline.md)
does not expose `missing_policy`, `objective_weights`,
`validation_data`, `plateau_window`, `plateau_tolerance`, or
`return_all_reps` for DGSI, and renames `select_mode = "eligible_top_n"`
to `"trait_thresholds"`. Two vocabularies for the same concept in one
package.

**Unsafe default in the pipeline.** `fallback_to_top_n = TRUE` means the
pipeline silently ignores the breeder’s eligibility thresholds when
nothing qualifies.
[`run_dgsi()`](https://FAkohoue.github.io/DesiredGainR/reference/run_dgsi.md)
defaults to `"error"`. The safe default should win, and in a package
built on “nothing happens silently” this one stands out.

**`debug = TRUE` defaults.**
[`run_dgsi_qgsi_pipeline()`](https://FAkohoue.github.io/DesiredGainR/reference/run_dgsi_qgsi_pipeline.md)
and
[`run_qgsi_desired_gain()`](https://FAkohoue.github.io/DesiredGainR/reference/run_qgsi.md)
default to verbose;
[`run_dgsi()`](https://FAkohoue.github.io/DesiredGainR/reference/run_dgsi.md)/[`run_qgsi()`](https://FAkohoue.github.io/DesiredGainR/reference/run_qgsi.md)
do not. Packages should be quiet by default.

**Deprecation mechanics.**
[`run_qgsi_desired_gain()`](https://FAkohoue.github.io/DesiredGainR/reference/run_qgsi.md)
uses a bare [`warning()`](https://rdrr.io/r/base/warning.html). Use
[`.Deprecated()`](https://rdrr.io/r/base/Deprecated.html) or a
`lifecycle` badge so it appears in the docs and in `R CMD check` output,
and give it a removal target in NEWS.

**Dead and duplicated code.**
[`.validate_square_matrix()`](https://FAkohoue.github.io/DesiredGainR/reference/dot-validate_square_matrix.md)
and `.desiredgainr_z()` are defined and never called;
[`.validate_square_matrix()`](https://FAkohoue.github.io/DesiredGainR/reference/dot-validate_square_matrix.md)
even has a generated `man/dot-validate_square_matrix.Rd`.
[`globalVariables()`](https://rdrr.io/r/utils/globalVariables.html) is
called in both `R/globals.R` and `R/utils_internal.R` with overlapping
and partly obsolete names (`Rank_LinearDGPart`, `SignSame_DG_QGSI`,
`..dg_cols_present`).

**Performance.** The search is `n_rep × n_iter` evaluations (default
20,000), each recomputing `X %*% b`, a full column-SD pass, `colMeans`,
and a sort of the whole pool. `apply(matrix, 2, sd)` and
`colMeans(matrix)` are loop-invariant and should be hoisted — that alone
is a large win. There is no parallelism over replicates
(`parallel`/`future.apply`) and no compiled code. On 20k candidates × 15
traits this will be slow enough to discourage use.

**`inst/CITATION` uses
[`citEntry()`](https://rdrr.io/r/utils/citEntry.html).** Deprecated
since R 4.2; modern `R CMD check` flags it. Switch to
`bibentry(bibtype = "Manual", ...)`.

**DESCRIPTION issues.** `Author:`/`Maintainer:` are hand-written
alongside `Authors@R` (redundant, can drift out of sync); no
`Depends: R (>= 4.1)` or similar; no `Language: en-GB` despite
consistent British spelling, which will trip CRAN’s spell check;
`Config/roxygen2/version: 8.0.0` should be verified against the roxygen2
actually used.

**Undocumented example data.** `inst/extdata/*.csv` have no data
documentation, no provenance, no units, and no description of
`YLD/MY/MI/BL/NBL/VHB`. The values are uncorrelated standard normals, so
`G ≈ I` and the examples cannot demonstrate the multi-trait behaviour
that is the entire point. Replace with a simulated dataset that has a
realistic `G` (documented correlations, heritabilities, trait means and
units) or a de-identified real trial.

**Missing `@examples`.**
[`run_dgsi()`](https://FAkohoue.github.io/DesiredGainR/reference/run_dgsi.md),
[`estimate_genetic_covariance()`](https://FAkohoue.github.io/DesiredGainR/reference/estimate_genetic_covariance.md),
and
[`compare_dg_and_qgsi()`](https://FAkohoue.github.io/DesiredGainR/reference/compare_dg_and_qgsi.md)
have none.
[`run_dgsi()`](https://FAkohoue.github.io/DesiredGainR/reference/run_dgsi.md)
is the flagship function.

## 5. Weaknesses — testing

Five test files, roughly 30 assertions. Untested paths include:

- [`run_dgsi()`](https://FAkohoue.github.io/DesiredGainR/reference/run_dgsi.md):
  `validation_data`, `objective_weights`, `mean_impute` and
  `complete_cases` policies, `scale_traits = TRUE`, non-PSD `G`
  rejection, `empty_eligibility = "fallback_top_n"`, plateau
  diagnostics, `ref_data` distinct from `cand_data`, `lower_is_better`
  sign propagation into `P`/`G`.
- [`run_qgsi()`](https://FAkohoue.github.io/DesiredGainR/reference/run_qgsi.md):
  `reference_gebv_data`, `scale_traits = TRUE`, rank-deficient
  `relationship_matrix` (the Moore–Penrose branch is advertised but only
  the full-rank branch is tested), `selection_proportion` edge values.
- [`run_dgsi_qgsi_pipeline()`](https://FAkohoue.github.io/DesiredGainR/reference/run_dgsi_qgsi_pipeline.md):
  `mode = "dg"` and `mode = "qgsi"` alone.
- Both `print` methods;
  [`compare_dg_and_qgsi()`](https://FAkohoue.github.io/DesiredGainR/reference/compare_dg_and_qgsi.md)
  legacy-column renaming.

More important than coverage: there are no **property tests against
known answers**. A specialist reviewer will look for (a) a case where
the closed-form Pesek–Baker `b` reproduces `d` exactly, (b) a
Monte-Carlo check that the QGSI `Var(I)` and `E(I)` formulas match
simulation from a multivariate normal `γ`, (c) a check that the expected
per-trait gain matches the realised gain under simulated truncation
selection. Test (c) would have caught §3.3 immediately.

No coverage measurement (`covr` + codecov workflow), no lint config, and
CI tests only `release` — add `oldrel-1` and `devel`.

## 6. What is missing (feature gaps for the target audience)

**Index families.** A package named for desired gains should implement
the theory-backed relatives: the restricted index (Kempthorne–Nordskog),
the null-restricted / Mallard index, and above all the **predetermined
proportional-gains index (PPG-LPSI, Tallis 1985; Cerón-Rojas &
Crossa)**, which is the formally justified version of what
[`run_dgsi()`](https://FAkohoue.github.io/DesiredGainR/reference/run_dgsi.md)
approximates by search. Also missing: Smith–Hazel LPSI and the linear
genomic index LGSI as baselines — without them the package cannot
reproduce the comparisons in the very paper it cites.

**Reporting a breeder expects.** Expected genetic response per trait
with standard errors, correlated response, index accuracy `ρ_HI`, index
heritability, selection differential vs expected gain, and gain per unit
time/cycle. The QGSI side has some of this; the DGSI side has almost
none.

**Diversity and constraint.** No coancestry or inbreeding control, no
optimal contribution selection, no mate allocation, no per-family or
per-group quotas beyond the single eligibility threshold. Real
programmes cannot select on gain alone, and this is the most commonly
requested feature in comparable tools.

**Upstream integration.** No adapters for the objects breeders actually
hold: [`sommer::mmer`](https://rdrr.io/pkg/sommer/man/mmer.html)
(`$sigma`, `$PevU`), ASReml-R (`vparameters`, `predict` PEV),
`lme4`/`breedR`, `rrBLUP`/`BGLR` GEBVs, `AGHmatrix`/`ASRgenomics`
relationship matrices. An `as_genetic_covariance()` S3 generic over
those classes would be the single highest-value addition for adoption,
and it fits the package’s provenance philosophy perfectly.

**Multi-environment and multi-stage.** No GxE handling, no
multi-environment index, no multi-stage/two-stage selection, no
across-cycle response prediction (Bulmer effect, drift of `G`).

**Elicitation and sensitivity for `W`.** The package correctly refuses
to invent `W`, but then offers the breeder no help constructing it. A
vignette (or helper) on translating agronomic and economic objectives
into `w` and `W`, with a sensitivity/tornado analysis over plausible
weight sets, would convert the current refusal from an obstacle into a
feature.

**Ill-conditioned input handling.** Bending / nearest-PD projection,
shrinkage estimators for `Γ` when `p` is large relative to `g`, and a
condition-number diagnostic. Currently non-PSD input is simply an error,
which will send users to ad-hoc fixes outside the package.

**Documentation gaps.** One vignette only. Worth adding: a real worked
case study end-to-end from a REML fit; a “choosing W” vignette; a
validation vignette reproducing the published QGSI results; and a
methods/theory vignette stating every estimand and the conditions under
which each reported number is valid.

**Publication and archiving.** No CRAN submission artefacts
(`cran-comments.md`), no Zenodo DOI, no JOSS/preprint. For a package
meant to be cited by breeders, a versioned DOI and a short methods paper
matter more than another feature.

## 7. Suggested priority order

1.  Resolve §3.3 (per-trait gain denominator) and §3.4 (`ρ²`) against
    the published supplementary equations; fix the tests that currently
    lock them in.
2.  Fix the `dg` scale ambiguity (§3.1) and add the closed-form expected
    response `i·Gb/√(bᵀPb)` and accuracy to the DGSI output (§3.2).
3.  Fix `Γ` centring consistency (§3.5), RNG state restoration, and
    tie-breaking.
4.  Replace the example data and rewrite the three examples so they no
    longer derive `G` from raw phenotypes (§3.7, §3.8).
5.  Add Monte-Carlo property tests for every theoretical formula.
6.  Add [`predict()`](https://rdrr.io/r/stats/predict.html),
    [`print()`](https://rdrr.io/r/base/print.html),
    [`summary()`](https://rdrr.io/r/base/summary.html),
    [`plot()`](https://rdrr.io/r/graphics/plot.default.html) for
    `desired_gain_index`.
7.  Add uncertainty propagation for `G`/`Γ` (bootstrap + sensitivity)
    (§3.6).
8.  Add the PPG/restricted index family and LPSI/LGSI baselines.
9.  Add upstream adapters (`sommer`, ASReml-R) and a real worked-example
    vignette.
10. Housekeeping: [`bibentry()`](https://rdrr.io/r/utils/bibentry.html),
    DESCRIPTION cleanup, dead code, CI matrix, coverage.
