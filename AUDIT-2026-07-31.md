# DesiredGainR 0.5.0 - current technical review

> **Superseded historical audit.** This report applies only to the package
> snapshot reviewed on 31 July 2026. The findings drove later remediation and
> do not describe the current 0.5.0 source. It is retained for provenance; use
> `MATURITY.md`, `NEWS.md` and `inst/validation/` for the current assessment.

Date: 2026-07-31
Scope: the improved package files supplied on 2026-07-31. This report
supersedes the earlier audits of the same date.

## Current verdict

The improved version resolves the previously reproduced high-risk failures in
covariance admissibility, hard culling, integer validation, simulation timing,
AlphaSimR state isolation, deterministic execution, and marker-based diversity.
The package is now substantially closer to an expert-quality research package.

It is not yet release-ready or a complete QG reference implementation.

Executable evidence from R 4.5.0, AlphaSimR 2.1.0 and ASRgenomics 1.1.6:

- 177 `test_that()` blocks;
- 545 passing assertions;
- 0 failures and 0 warnings in `devtools::test()`;
- 3 skipped assertions, two because the rendered Breeder Guide is absent;
- source tarball and all five vignettes build successfully;
- standard `R CMD check`: 0 errors, 2 warnings;
- `R CMD check --as-cran`: 0 errors, 2 warnings, 3 environmental notes; and
- all examples, `\donttest{}` examples, installed tests, and rebuilt vignettes
  pass.

Both package-check warnings come from one malformed display equation in
`man/index_uncertainty.Rd`. The CRAN notes arose because this environment is
offline, could not verify its clock, and did not propagate Pandoc into one
top-level check. They are not evidence of package defects, but URLs should be
rechecked online before submission.

The strongest current components are the objective tools, classical index
algebra, covariance diagnostics, QGSI input safety, and the repaired core
simulation semantics. The most important unresolved scientific issue is a
units inconsistency in `run_dgsi()` when `scale_traits = FALSE`. The simulation
optimiser remains experimental because its checkpoints and uncertainty model
are not yet adequate for an auditable recommendation.

## Previously blocking findings now resolved

### Joint covariance validation

`selection_index()` and `evaluate_index()` now require `P - G` to be positive
semidefinite. `run_qgsi()` requires `true_G - Gamma` to be positive
semidefinite before accuracy or MSPE is reported. Numerically tiny correlation
excursions are clamped only after admissibility is established.

The earlier probes producing index heritability 2, accuracy 1.414, QGSI MSPE
-1 and squared correlation 2 now fail with explanatory errors.

### Hard independent culling

`n_select` is now a maximum for independent culling. Failed candidates cannot
fill a shortfall, the actual selected count drives selection intensity, and a
candidate-level gate-failure report is returned.

### Strict integer validation

Fractional, missing, infinite, zero and negative counts are rejected before
integer coercion. `run_dgsi(n_select = 1.9)` no longer truncates silently.

### Pipeline defaults

`fallback_to_top_n` and `debug` now default to `FALSE`. Explicit fallback emits
a warning and is recorded in pipeline provenance.

### Selection-cycle timing

Cycle 0 now records founders. Cycle `t` records descendants produced from
parents selected in cycle `t - 1`, so `n_cycles = 1` is one transmitted
response. Common-random-number tests confirm different desired-gain directions
can produce different one-cycle gains.

### AlphaSimR isolation and reproducibility

`SimParam` is deep-cloned, one thread is the default, multiple threads warn,
and simulation provenance records software versions, seed and requested
thread count. Repeated one-thread runs are identical and the caller's
`setup$SP$lastId` remains unchanged.

### Diversity measurement

Founder frequencies are fixed. A separately retained SNP panel can now be held
disjoint from QTL, marker-based coancestry is separated from QTL segregation
and genic-variance loss, and the incorrect self-centring test identity has been
repaired.

### Clonal variance calibration

Dominance setups now distinguish narrow- and broad-sense heritability and
iteratively calibrate the realised genotypic variances to the supplied target.
Sexual crossing and clonal evaluation phases are explicitly distinguished.

### Documentation coverage

The new exported functions and S3 methods now have generated manual pages and
the previous stale print-method mismatch is resolved.

## Release-blocking issues

### R1. `index_uncertainty.Rd` contains invalid Rd mathematics

The roxygen source contains a raw Markdown/LaTeX display:

```text
$$\mathbf{G}^{*} \sim \mathcal{W}_p(\nu_g,\; \mathbf{G}/\nu_g),$$
```

It is copied literally into the Rd file, where `\mathbf`, `\sim`, `\mathcal`
and `\nu` are parsed as unknown Rd macros and braces are lost.

Fix the R source with `\deqn{...}`, regenerate documentation, and require a
source-tarball check with zero warnings. Do not edit only the generated Rd.

### R2. The Breeder Guide is still not installed

`inst/guide/DesiredGainR_Breeder_Guide.Rmd` now exists and its HTML edition
renders successfully. Neither generated edition is present under
`inst/extdata`, where `open_desiredgain_guide()` looks.

Consequences:

- the exported function errors in the installed package;
- the README promises a guide that cannot be opened;
- the pkgdown navbar links to a page that will not be produced; and
- two guide tests skip instead of enforcing the release contract.

Generate and commit at least the HTML artifact before release. Either generate
the PDF too or change the default format from PDF to HTML. The pkgdown workflow
must fail, not merely warn, when the navbar target is missing. Release CI must
not skip the installed-artifact test.

### R3. `inst/CITATION` is stale

`DESCRIPTION` and `CITATION.cff` say version 0.5.0, while `inst/CITATION` still
reports version 0.3.1 in both its note and text citation. Generate the citation
from package metadata or update all three sources together and test their
agreement.

## Major scientific and decision-quality issues

### M1. DGSI desired-gain units are inconsistent when traits are not scaled

`run_dgsi()` documents `dg` as candidate-standard-deviation units regardless
of `scale_traits`. Its optimisation objective follows that definition by
standardising selected differentials.

When `scale_traits = FALSE`, however, the Yamada coefficient map uses raw `G`
and `P` and passes the SD-unit proposal directly as `d`:

```text
b = P^-1 G (G P^-1 G)^-1 d = G^-1 d
```

For equal requested SD gains and candidate SDs 10 and 1, this produces raw
response proportional to `(1, 1)`, hence standardised response proportional to
`(0.1, 1)`, not `(1, 1)`. The stochastic search can partly compensate because
the map is invertible, but:

- its proposal coordinates are mislabeled;
- `optimised_d` is not in the documented units;
- the non-iterated Yamada comparator is scale-wrong; and
- proposal step sizes depend on the wrong parameterisation.

Convert SD-unit desired gains to the covariance-matrix trait scale before the
coefficient solve, or always perform the solve in a consistently standardised
space. Add an invariance test showing that changing trait measurement units
does not change selected candidates or standardised response.

### M2. Optimiser checkpoints still identify only column names

`optimize_desired_gains()` accepts a checkpoint when `trait_cols` and
`objective_names` match. It does not fingerprint founder genomes, `G`, mating
system, cycle count, parent/cross design, replicate count, seed, marker basis,
or package/AlphaSimR versions.

A checkpoint can therefore resume results from a different scientific problem.
Store and verify a stable fingerprint of every result-defining input. A
mismatch should stop unless the user explicitly discards the saved state.

### M3. Simulation standard errors are computed and discarded

`.dgr_evaluate_direction()` returns Monte Carlo means and standard errors, but
`optimize_desired_gains()` saves only `outcome$mean`. The Gaussian process then
fits an estimated homogeneous nugget instead of using known direction-specific
simulation error.

Retain replicate-level outcomes or at least their covariance and SE. Use them
in a heteroskedastic surrogate and report uncertainty in Pareto dominance,
frontier membership and the recommended region.

### M4. Covariance uncertainty does not reach the recommendation

`index_uncertainty()` is a useful, transparent approximate sensitivity tool.
Simulation and direction optimisation still condition on one fixed covariance
estimate. A Pareto frontier therefore has Monte Carlo and covariance-estimation
uncertainty but is displayed as a set of points.

Add an outer covariance-draw layer using jointly admissible `G` and residual
draws, and report rank churn and frontier-membership probabilities. Keep the
fixed-`P` option labelled as local sensitivity, not a full generative model.

### M5. Diversity optimisation remains enabled without requiring a clean panel

`include_diversity = TRUE` remains the optimiser default, while
`n_markers_per_chromosome` is optional. Without a SNP chip, diversity falls
back to all segregating sites, which includes QTL. On older supported AlphaSimR
versions, a requested marker panel may also overlap QTL.

Require a verified disjoint marker panel when diversity is an optimisation
objective, or default `include_diversity` to `FALSE`. At minimum, stop or issue
a prominent warning when `marker_qtl_overlap` is not explicitly `FALSE`.

### M6. Clonal mode matches variances, not the full covariance target

The new calibration correctly targets each genotypic variance. Genotypic
correlations remain emergent from the additive/dominance architecture and may
differ from the supplied `G`; differences above 0.15 only warn.

This is honestly documented and `G_realised` is returned, but the setup does
not reproduce the full covariance matrix it accepts as a target. Either
calibrate the complete covariance structure, make the accepted target explicitly
diagonal-plus-additive-correlation, or require explicit acceptance when the
realised correlation discrepancy is material.

Clonal evaluation also has no clone-replication parameter. Each seedling gets
one phenotype, so the higher precision produced by replicated clonal trials is
not represented. Add clonal replication or an explicitly stage-adjusted error
variance before using this mode for operational recommendations.

### M7. Estimated `P` compatibility is warned about but not enforced or stored

When `P` is user supplied, `run_dgsi()` enforces `P - G` admissibility. When
`P` is estimated from reference candidates, the function permits an
inadmissible pair and warns only when the negative eigenvalue exceeds an
approximate sampling threshold.

That pragmatic exception should be explicit in the API. Record the smallest
eigenvalue, threshold, compatibility status and any override in covariance
provenance. Prefer a fitted joint `P`/`G`, or require an explicit
`allow_incompatible_estimated_P` acknowledgement for continued use.

### M8. Best-of-replicate DGSI optimism is reported, not removed

The new optimism report is useful. The winning stochastic search is still
chosen on the candidates it then selects. `validation_data` evaluates the
winner after selection but does not choose among replicates, so it does not
remove selection bias.

Use held-out candidates or nested resampling to choose the replicate, or
aggregate replicate solutions before final selection. Continue reporting the
current gap as a sensitivity diagnostic.

### M9. DGSI lacks the standard theoretical transmitted response

`run_dgsi()` reports a standardised empirical differential in the supplied
candidate set. It should also report the classical model-based response

```text
i G b / sqrt(b' P b)
```

in analysis and original trait units. This is needed to distinguish a selected
sample differential from expected inherited response and to compare DGSI with
classical indices on the same QG criterion.

### M10. Requested threads are recorded even if assignment fails

`SP$nThreads <- n_threads` is wrapped in `tryCatch()` for old AlphaSimR
versions, but provenance always records the requested value. If assignment is
unsupported, a run can remain multithreaded while claiming one thread.

Read and record the effective thread count. Stop or warn when it cannot be set
to the requested value. Reconsider the declared AlphaSimR minimum if older
versions cannot meet the reproducibility contract.

### M11. Marker-panel mismatches can silently change the diversity basis

When a stored panel is supplied, `.dgr_diversity_geno()` intersects its names
with available genotype columns. Missing panel loci are silently dropped; if
none match, the full genotype matrix is used.

Require the exact panel, order by marker identifier, and stop on missing loci.
Store marker IDs retained after the founder polymorphism filter rather than a
position-only logical vector.

### M12. The optimiser can evaluate the same direction repeatedly

Chosen candidate-pool directions are not removed or marked as evaluated. With
a fitted nugget, expected improvement at an observed point can remain positive,
so a finite budget may be spent on duplicate directions without treating them
as purposeful additional replication.

Exclude evaluated directions, or explicitly combine duplicates as extra
replicates and update their mean and Monte Carlo variance.

### M13. Numeric control validation is incomplete

The new strict count validation is good, but seeds are still coerced with
`as.integer()` in `run_dgsi()`, `optimize_desired_gains()` and sensitivity
tools. Fractional seeds can therefore truncate. Replicate seed arithmetic can
also exceed the integer range.

Use `.dgr_seed()` consistently and check derived seeds. Validate `ridge_P`,
`ridge_M`, `plateau_tolerance` and similar scalar controls for length one,
finiteness and their documented ranges.

### M14. Covariance bending remains an aggressive repair

`bend_covariance()` is transparent and its tests now pass, but
ASRgenomics::G.tuneup() fixes `keepDiag = FALSE` and `posd.tol = 0.01`. It can
materially change trait variances and cap the condition number near 100 even
when a trait covariance legitimately contains weaker directions.

Continue treating bending as an explicitly reported repair, never an estimate.
For expert use, consider a trait-covariance-specific near-PD interface with
documented diagonal and eigenvalue-floor choices.

## Software-quality and competitive gaps

### Q1. CI coverage is too narrow

Current CI checks release R on Linux, Windows and macOS. Add:

- R-devel, R-oldrel and the declared minimum R 4.1;
- a mandatory AlphaSimR and ASRgenomics job that does not skip simulation or
  bending tests;
- test coverage and linting;
- a source-tarball check without regenerating documentation silently;
- a check that roxygen produces no uncommitted changes; and
- a mandatory rendered-guide check.

### Q2. Important classical index families are still absent

Add restricted and predetermined-proportional-gain formulations, especially
Kempthorne-Nordskog, Mallard, Harville and Tallis methods. These are the
closed-form expert comparators for constraints currently addressed through
stochastic search or hard eligibility gates.

### Q3. There is no multi-environment/GxE model

The package has no environment-specific covariance, stability/adaptability
objective, repeated-measure structure or stage-specific selection criteria.
At minimum, document an upstream contract and provide an example that imports
a fitted multi-environment covariance.

### Q4. No frozen published-data reproduction exists

Monte Carlo equation tests are strong internal evidence, but there is no
vignette reproducing coefficients, rankings or response from a published data
set or independent package. Add one frozen reproduction with stated numerical
tolerances and provenance.

### Q5. Upstream interoperability remains manual

Add adapters or validated examples for common mixed-model and breeding outputs
such as ASReml-R, sommer, breedR, StageWise and BGLR. Every adapter should check
trait order, units, identifiers, favourable direction and covariance estimand.

### Q6. Legacy example CSVs remain unresolved

`inst/extdata/example_gebv.csv` and `example_pheno.csv` coexist with the newer
coherent packaged example data. Document their distinct purpose and provenance
or remove them to avoid two competing example contracts.

### Q7. Fitted-object ergonomics remain incomplete

The classical index has `print()` and `predict()`, but expert workflows would
benefit from stable `summary()` and `coef()` methods and explicit tidy tables
for coefficients, expected response, uncertainty and provenance. DGSI and the
simulation optimiser should expose similarly consistent methods.

### Q8. Feature maturity is not explicit enough

Label the objective and classical-index layers stable, covariance uncertainty
beta, and recurrent simulation/optimisation experimental until M2-M12 are
resolved. The website currently presents these layers together without a clear
maturity boundary.

### Q9. CRAN and scholarly release work remains

After a zero-warning check:

1. verify all URLs and ORCID online;
2. submit to CRAN;
3. archive a release with a DOI;
4. publish the method and validation study; and
5. add a real breeding-program case study.

## Recommended implementation order

### Gate A - clean release candidate

1. Fix the invalid Rd equation.
2. Render and install the guide, or remove its public promise.
3. Synchronise `inst/CITATION` with version 0.5.0.
4. Fix DGSI unit conversion and add measurement-unit invariance tests.
5. Require a verified marker panel whenever diversity is optimised.
6. Make effective thread count and marker identity strict provenance.
7. Obtain `R CMD check` with zero errors and zero warnings.

### Gate B - auditable simulation recommendation

1. Fingerprint checkpoints.
2. retain and model simulation SE/covariance;
3. integrate covariance uncertainty;
4. prevent or deliberately combine duplicate direction evaluations;
5. address clonal covariance and replication limitations; and
6. report theoretical DGSI response and remove replicate-selection bias.

### Gate C - expert reference and distribution quality

1. Add restricted/proportional-gain indices;
2. add multi-environment support or an upstream contract;
3. reproduce published data independently;
4. expand CI, coverage and linting;
5. add adapters and consistent S3 summaries; and
6. complete CRAN, DOI, paper and programme case-study releases.

## Final assessment

The improved files move DesiredGainR from a package with several reproducible
scientific correctness failures to a well-tested research package with a small
number of identifiable release defects and a concentrated set of modelling
and optimiser limitations. The classical and QGSI layers are close to expert
quality once the DGSI unit inconsistency and release warnings are corrected.
The simulation core is now credible for research comparisons under its stated
assumptions; the optimiser should remain experimental until checkpoints and
both sources of uncertainty are made auditable.
